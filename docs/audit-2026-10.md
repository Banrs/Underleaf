# Audit, October 2026: Windows parity and the core's size

Two questions from the owner (2026-10-19): is the Mac app twice the Windows app's size because Windows
lacks features, and why is the Rust core so big? Counted on `main` at 23afe3b, in physical lines of
tracked files.

## In short

- **Swift against Windows.** The Mac app is 10,253 lines; Windows is 4,915 lines of C# and XAML,
  equally dense (38 characters a line). Of the Mac's extra 5,300 lines:
  - about 2,000 are features Windows lacks (live preview 500 and PDF find 350 the largest);
  - 1,300 are heavier plumbing (typed models for every event, AppKit around SwiftUI, project state
    in Swift);
  - 250 are extra workarounds for AppKit, TextKit and PDFKit;
  - 1,750 are richer versions of shared features.

  Tests: 2,756 Mac lines (134 tests), 180 Windows lines (15 tests).
- **The Rust core.** 23,300 lines: 9,689 (42%) are tests, and the 13,611 others hold 2,065 comment and
  1,034 blank lines. It owns what both apps share:
  - sessions (2,700);
  - the editors' LaTeX logic (4,150);
  - TeXpresso (1,400);
  - builds and logs (880);
  - import and export (720).

  Little is dead. The fat is generality no host uses, server- and web-era leftovers, duplicate
  readers, tests that check one rule at two or three levels, and seven test binaries that each
  link the whole core. Much of it accumulated as agents wrote the code
  ([why agent code runs long](#why-agent-written-code-runs-long)).

### Why agent-written code runs long

- **This code base was written by agents,** over about 1,500 commits.
- **Agents write long code.** SlopCodeBench ([arXiv 2603.24755](https://arxiv.org/abs/2603.24755))
  measured 15 agents' code as 2.3 times as verbose as 473 human repositories, and 2.0 times as
  eroded, meaning complexity collects in a few functions.
  - Both grow with each turn, because agents patch new logic into what exists instead of
    restructuring it.
  - The verbose patterns: defensive checks, trivial wrappers, single-use variables, if/else
    ladders, and comments no person would write.
- **Prompts don't fix it.** A quality prompt cut the starting verbosity by about a third, but not
  its growth per turn.
- **Agents skip reuse.** They often don't reuse what exists, so redundancy rises
  ([arXiv 2601.21276](https://arxiv.org/abs/2601.21276)), and copied code has overtaken moved code
  ([GitClear 2025](https://devclass.com/2025/02/20/ai-is-eroding-code-quality-states-new-in-depth-report/)).
- **Leftovers stay.** Agents keep the speculative edits of abandoned attempts; replaying and
  minimising those edits removes 18–33% of them ([TRIM, arXiv 2607.18161](https://huggingface.co/papers/2607.18161)).

Every one of these shows here:
- generality no host uses: a session taking over another's preview, eight timings nobody sets,
  two-name locks;
- server-era commands: `read_file`, `write_file`, `set_settings`, `get_ui_state`;
- a Tauri upload cap, and build "supersede" for several browser clients;
- two readers for one argument shape, and three "left out" rules;
- tests of one rule at two or three levels, random and wall-clock loops (nine tests take 13.7 s),
  and fixtures shared with the deleted web client.

Human repositories erode too (53% of them in SlopCodeBench), only more slowly. AGENTS.md now has a
"Writing code" section with the rules against both.

### What this branch cut

Every part of the repo had a pass under AGENTS.md's "Writing code" rules, except the Windows files
the unmerged redesign rewrites (`HomePage`, `MainWindow`, `WorkspacePage`, `Generic.xaml`,
`Sizer.cs`, `install.ps1`, docs/windows.md).

| Part | Before | After | Net |
|---|---:|---:|---:|
| Rust, non-test | 13,611 | 12,929 | −682 |
| Rust, test | 9,689 | 8,695 | −994 |
| Rust fixtures (logs, JSON) | | | −447 |
| Mac app | 10,253 | 10,045 | −208 |
| Mac tests | 2,756 | 2,693 | −63 |
| Windows app and tests | 4,915 | 4,775 | −140 |
| Tools and .gitignore | | | −85 |

- **Core:** the server-era commands (`read_file`, `write_file`, `set_settings`, `get_ui_state`,
  `session_state`), build supersede, the drop's 100 MB cap, a session taking over another's
  preview, `create_entry`'s `free`, the syntax answers no host reads, and the typing benchmark
  are gone; one argument reader and one "left out" rule remain where there were two or three. Hosts see each change in core-api.md's "Changes for hosts".
- **Modules:** all but `events`, `service`, `session` and `syntax` are private, so the
  compiler now reports what only tests use; it found one function.
- **Tests:** they run inside the crates, so three test binaries link the core instead of seven,
  and texlocal-ffi is a static library alone. 296 tests became 232, each rule checked once; the
  whole suite runs in about a second, where nine tests took 13.7 s.
- **Apps:** comments that restated the code, single-use members and guards for states the
  callers rule out. No Swift compiler ran here: Mac CI is these edits' first build.
